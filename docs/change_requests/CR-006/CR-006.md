# CR-006 — Report button on each Auditor batch row

| | |
|---|---|
| **Kind** | **A (frontend only)** |
| **Module** | Auditor → Audit Batches list |
| **Commit** | `9c443bc` |
| **Score impact** | None |
| **IT action** | `git apply frontend.patch`. It uses the existing `GET /auditor/batches/{id}/report.pdf` |

## What changes

Each audit batch row gets a **Report** button, matching PracticeLab's batch list. It downloads that batch's performance PDF without opening the batch.

- **Disabled with a reason** ("No scored results yet — nothing to report on") when the batch has 0 scored. The PDF is built from scored results. The button isn't hidden, so it's never a puzzle where it went.
- The row stays clickable and still opens the batch, but it's now a `div` with `role="button"`: a `<button>` can't contain another button. Click, **Enter** or **Space** opens it, and the Report button stops the click from reaching the row. `box-sizing: border-box` keeps the row at the width it had as a button.

## Verified

In a browser at 1366×900: 3 rows with scored results had Report enabled and the one with none had it disabled; the PDF downloads; clicking and pressing Enter on a row both open the batch; Report doesn't open the batch; no page overflow; no console errors.
