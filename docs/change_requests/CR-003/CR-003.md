# CR-003 — Code descriptions on review, DRG, key-check, auditor-review and analytics screens

| | |
|---|---|
| **Kind** | C (backend + frontend). No schema change |
| **Module** | PracticeLab trainer and coder screens; Auditor trainer review; analytics |
| **Depends on** | CR-001 (it adds descriptions to CR-001's review rows and export) |
| **Score impact** | None. Display only |
| **Order for IT** | Backend first, then the frontend patch. If the patch is applied first, the review screen shows codes without descriptions until the backend adds them. The other screens use the existing `GET /codes/describe` route and work immediately |
| **Commit** | `08e8b3a` |
| **Status** | Built and verified in the original app. Not yet implemented in .NET |

---

## 1. Why

Code descriptions appeared only where codes are **typed**: the coder and auditor forms and the key editors. Screens where codes are **read and judged** showed bare codes. That includes the DRG error decision, which affects pay. CR-001's new review screen also moved the coder's descriptions into a collapsed block.

## 2. What changes

| Screen | What it shows now |
|---|---|
| Post-submit **review** (trainer Review modal, coder results) | Each code in the Answer key and Coded columns has its description beneath it, at most 2 lines, with the full text on hover |
| Review **Excel export** | Review sheet gains **Key description** and **Coded description** columns, after Answer key and after Coded |
| Trainer Review **Scoring notes** | Descriptions under the codes, taken from the review (no extra lookup) |
| **DRG Review** | Each finding becomes a fixed grid: section · issue · *Answer key* (code + description) · *Coder* (code + description + detail) |
| **Answer-key Check Codes**, CC/MCC panel | One row per issue in fixed columns: chart · code · description (1 line, full text on hover) · key vs CMS. The list scrolls inside the panel. The "not a CMS code" panel is unchanged, since those codes have no description by definition |
| **Auditor review** (trainer) | Under each planted error and over-call whose field is the **code**, one line per code: code + description. POA, modifier and units values aren't codes, so they show none |
| **Most-missed codes** chips: batch Results, Insights, by-coder analytics | Description as a hover tooltip; the chips stay compact |

**Never described** (unchanged rule): CPT, i.e. five-digit codes and E/M levels (AMA licence), and MDM, time and text rows. A code with no description, an unloaded code set or an unknown code shows the code alone. It never errors.

**Layout rule** applied everywhere: descriptions wrap or truncate inside their own column and never widen a row or the page. Checked on every screen above with the longest real descriptions (e.g. a 90+ character PCS title). No page-level horizontal overflow.

## 3. Backend: implement in .NET

### 3.1 Review rows gain two fields

Every row in a review section whose `key` is `pdx`, `sdx`, `dx`, `pcs` or `cpt` gains:

```json
{"item": "SDx", "key": "I10  POA Y", "coded": "I10  POA Y", "status": "correct", "note": "",
 "key_desc": "Essential (primary) hypertension", "coded_desc": "Essential (primary) hypertension"}
```

- The code is the text before the first double space in `key` / `coded`.
- Code system by section: `pdx`, `sdx`, `dx` → ICD-10-CM · `pcs` → ICD-10-PCS · `cpt` → HCPCS. A five-digit CPT code has no row in HCPCS, so it comes back empty.
- Look up without dots and spaces, upper-case, from `code_descriptions` (the `description` column), using **one query per code system for the whole session**, not one per row.
- Empty string when not found. Any lookup failure leaves both fields empty and must not fail the response.
- Rows in `em_level`, `copa`, `dr`, `risk`, `time`, `mdm` and `ed` sections **do not** get these fields.

Applies to the three routes that carry `review` (CR-001 §4.1) and to both exports.

### 3.2 Export

Review sheet columns become: Chart · Score % · Section · Points · Item · Answer key · **Key description** · Coded · **Coded description** · Result · Note. The Result colouring moves to column 10. The two description columns are 40 wide and wrapped.

## 5. Acceptance tests

1. With the code sets loaded, a submitted IP session's `GET .../review` returns `key_desc` = `Pneumonia, unspecified organism` on the J18.9 PDx row. `backend/tests/test_practice_review.py → test_review_rows_carry_what_each_code_means` pins this.
2. Its export's Review sheet has *Key description* in column G and *Coded description* in column I.
3. A code not in `code_descriptions` gives empty descriptions, and the response is still 200.
4. E/M level and MDM rows carry no description fields.
5. **Visual check:** open the review, DRG Review, Check Codes and auditor review screens on a chart with a long PCS description. Nothing should run past its column, and the page shouldn't scroll sideways.
