# CR-002 — E/M primary diagnosis becomes a scoring factor; diagnosis dots ignored

| | |
|---|---|
| **Kind** | B (backend only). No schema change, no frontend change |
| **Module** | PracticeLab: E/M and ED Profee grading |
| **Depends on** | CR-001 (its review Diagnoses section is replaced by §4 below) |
| **Commit** | `bccf4ff` |
| **Score impact** | **Yes.** It changes the score of any E/M or ED Profee chart where the primary diagnosis isn't listed first, or where a diagnosis was typed without its dot |
| **Status** | Built and verified in the original app. Not yet implemented in .NET |

---

## 1. Why

1. **Primary diagnosis didn't count.** E/M scored diagnoses as an unordered set, so a coder who coded the right primary but listed it last lost nothing. The user confirmed on 2026-11-19 that the primary diagnosis is a scoring factor. IP/OP already scores PDx as its own all-or-nothing component.
2. **Dots cost points.** The coder's diagnosis box says *"dot optional"*, but E/M compared codes with dots kept. A coder typing `E119` against a key of `E11.9` scored it as wrong. Measured: the same three correct codes scored **8.8 of 35** typed without dots and 35 of 35 with them. IP/OP already ignores dots.

## 2. The rule (implement exactly)

Let **W** be the chart's Dx weight: the renormalised weight already applied today. It's 23.34 normally and 35 when the key has no CPT. Diagnoses are cleaned before every comparison: trim, upper-case, **remove dots**.

| Part | Worth | Earned when |
|---|---|---|
| **Primary** | **W/2**, or **W** if the key lists only one diagnosis | the coder's **first** code equals the key's **first** code. All or nothing. Coded at any other position, it earns **no** primary credit and doesn't count as a secondary either |
| **Secondaries** | **W − primary share**, split evenly across the key's codes after the first | each key secondary found **anywhere** in the coder's list |
| **Over-coding** | unchanged | each code the coder lists beyond the key's count costs **W ÷ (number of key codes)** |
| **Key lists no diagnoses** | unchanged: full W | |

`Dx score = max(0, primary + secondaries − over-coding penalty)`

Unchanged: the 70/30 coding/reasoning split, every other weight, and the stored feedback line format `Dx: x/y pts`.

Applies to **E/M and ED Profee** (one grader).

Dots are now removed everywhere the E/M grader cleans code lists, which includes the diagnosis list used to resolve CPT pointers. CPT codes contain no dots, so they're unaffected.

## 3. Past results

**Stored scores are not rescored.** Results keep the score they were graded with. New submissions use the new rule, and a trainer's **Re-grade** on a session applies it to that session. Analytics will mix both rules until older sessions age out.

## 4. Review screen: replaces CR-001 §3.4

The E/M **Diagnoses** section (`key: "dx"`) keeps its one score and its rows, now explained by the rule above:

- **Primary Dx row:** key = the key's first code, coded = the coder's first code.
  - equal → `correct`
  - different → `different`. If the key's primary appears later in the coder's list, the note is `Coded at position N, not first: no primary credit. The primary must be listed first`; if it doesn't appear at all, the note is `Not coded`
  - coder has no codes → `missed`
- **Secondary Dx rows:** the key's remaining codes compared as a multiset (CR-001 §3.2) against the coder's list minus the code the Primary row used.
- **Section note:** `Primary p of P pts (must be listed first) · Secondary m of n coded, s of S pts[ · k over-coded, -x pts]`.
- **A result graded before this CR:** if the stored Dx points differ from the points this rule gives, the note is prefixed with `Scored under the earlier rule, where diagnosis order did not count (x pts). Re-grade the session to apply the current rule: …`. The screen mustn't show parts that don't add up to the stored score.
- Codes display as entered (with or without dots) but compare without dots.

## 5. Acceptance tests

Key `E11.9, I10, J45.909`, W = 35 (no CPT):

| Coder lists | Dx score | Why |
|---|---|---|
| E11.9, J45.909, I10 | **35.0** | primary first; both secondaries |
| I10, E11.9, J45.909 | **17.5** | primary not first: 0 of 17.5; secondaries 2 of 2 |
| I10, E11.9 | **8.8** | primary 0; secondaries 1 of 2 (8.75) |
| E11.9 | **17.5** | primary only |
| E119, I10, J45909 | **35.0** | dots ignored |
| E11.9, I10, J45.909, R05.9 | **23.3** | full 35 − one over-coded × 35/3 |

Key `E11.9` alone: coder `E11.9` → 35.0; coder `I10` → 0.0. Key with no diagnoses → full 35.

These are pinned in `backend/tests/test_practice_review.py`. Removing the "listed first" condition makes three of them fail.

## 6. Reference implementation (for reading, not porting)

`backend/routers/practicelab_pkg/em_grading.py → score_em_dx()`, called from `grade_em_chart`. `_clean_codes()` now removes dots. The review uses the same function in `backend/services/practice_review.py → _em_sections`.

## 7. Risk and rollback

- Scores fall for coders who list the primary later. That's the intent, but trainers should hear about it before a batch is compared against older batches.
- Rollback: restore the previous Dx block. No data changes.
