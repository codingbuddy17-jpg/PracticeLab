# CR-005 — CMS POA exempt list applied everywhere POA is keyed, coded, audited or graded

| | |
|---|---|
| **Kind** | **C + D**: backend, frontend **and a schema column** |
| **Module** | Code sets · PracticeLab (coder form, key editor, key upload, grading) · Auditor (screen, authored errors, error generator) |
| **Commits** | `6e32710` · `2847e8b` (status tile; patch: `frontend-amendment-2847e8b.patch`) |
| **Score impact** | **Yes.** POA on an exempt code is no longer graded, so a coder previously marked wrong on one is not on a re-grade. Existing inpatient keys are corrected to E once |
| **Order for IT** | 1. DDL (§4) · 2. backend rules (§3) · 3. run the loader (§2) · 4. apply `frontend.patch` |
| **Status** | Built and verified in the original app. Not yet implemented in .NET |

---

## 1. Why

CMS exempts about 38,000 ICD-10-CM codes from present-on-admission reporting: history codes, external-cause place codes, liveborn and delivery encounters, and others. Nothing in the app knew which codes they were. So:

- Trainers checked the CMS list by hand when building keys and picked **E**; coders and auditors did the same.
- Keys with Y/N on an exempt code marked a coder **wrong** for entering E, the correct answer.
- The auditor's error generator planted POA errors on exempt codes. On an exempt code keyed Y, it planted "N, should be Y", which is wrong twice over: the right value is E.

## 2. The list (code-set loader)

- **Source:** `https://www.cms.gov/files/zip/{FY}-poa-exempt-codes.zip`. The loader tries the current fiscal year first, then the previous one. Inside the zip, `POAexemptCodesFY27.txt` is tab-delimited with header `Order27 · POAexemptCode · Description`. Find the code column **by its header** (the order column is renamed every year). Codes arrive dotted (B90.0) and are stored bare (B900).
- **FY2027:** 38,399 codes, all present in the FY2027 ICD-10-CM set.
- **Stamped onto `code_descriptions.poa_exempt`** for each ICD-10-CM row when the CM set loads: `TRUE` / `FALSE`, or `NULL` when no list was found. **NULL means unknown, and every reader must treat it as "change nothing"**, never as "not exempt".
- Offline (`--from-dir`): the file is matched by name containing `poaexemptcodes`. **Trap:** that file name also contains "codes" and sorts first. The CM codes-file lookup must exclude names containing "poa", otherwise the exempt list is loaded as the ICD-10-CM set.
- After loading, **existing inpatient keys are corrected once** (§3.3), and the loader prints how many.
- `scripts/ingest_code_sets.py` is standalone Python that writes only the code tables and the key correction. IT can run it against their PostgreSQL as-is (`DATABASE_URL=... python scripts/ingest_code_sets.py --write`), or reproduce it.

## 3. Rules (implement exactly)

"Exempt" means `code_descriptions.poa_exempt IS TRUE` for the ICD-10-CM code, compared bare (no dots, upper case). **POA applies to IP-DRG only.** Other specialties are untouched.

### 3.1 Grading (IP)
- **PDx:** with the code right, the PDx earns its points whatever the POA, if the code is exempt.
- **SDx matching:** a key line and a coder line match on code alone when the code is exempt (POA isn't compared).
- **POA accuracy (DPO):** an exempt code is **not a POA opportunity**. Neither the opportunity nor a defect is counted.
- The list isn't loaded → grading is exactly as before.

### 3.2 Auditor error generator
- Never plant a POA error on a line whose code is exempt (PDx or SDx).
- A chart whose only POA-bearing lines are exempt isn't eligible for a POA error. Choose another error kind.

### 3.3 Answer keys (IP)
On **every save** (Excel upload, insert or replace, and the key editor) **and once after the list loads** for all existing keys: every exempt code's POA becomes **E**, whatever it was (Y, N, U, W or blank).

## 4. Database (Kind D)

```sql
ALTER TABLE code_descriptions ADD COLUMN poa_exempt BOOLEAN;   -- nullable, no default
```

This is a new column on an **existing** table, so it needs IT's migration step; schema-from-model won't add it. Verified here against a pre-existing table: boots, column added, no migration failure.

## 5. API (not visible in OpenAPI)

- `GET /codes/describe` → each `descriptions[code]` gains `"poa_exempt": true | false | null`.
- `GET /codes/status` → gains `"poa_exempt_loaded": true | false` and `"poa_exempt_codes": <count>` (counted in SQL). `needs_attention` is also true when ICD-10-CM is loaded without the exempt list.
- **Code Set Maintenance** shows a **POA exempt list** tile: "38,399 exempt codes" when loaded, red "not loaded — run the ingest" when not. Added after the first deploy, because a completed ingest gave no confirmation that the list had loaded.

## 6. Screens (`frontend.patch`)

New `components/PoaSelect.tsx`: when the code beside it is exempt, the POA box shows a greyed **E · POA exempt** (CMS tooltip) and **sets the value to E itself**. If the code is changed to a non-exempt one, an E the box set is cleared, so the person must choose. It checks after every render, so several rows turning exempt at once all get E; a single dependency-triggered check lost all but the last.

| Screen | Behaviour |
|---|---|
| Coder form, IP PDx and SDx | auto E, greyed |
| Key editor, PDx and SDx | auto E, greyed |
| Auditor, **Add** rows | auto E, greyed |
| Auditor, **claim** lines | locked E when the claim already shows E or blank. Follows the auditor's **revised** code. If a claim from before this change shows Y/N on an exempt code, it stays editable with "POA exempt — should be E", so a planted error stays correctable |
| Auditor authored-error editor | the "wrong POA" input is disabled on exempt codes |

`exempt` null (list not loaded) → every box is unchanged.

## 7. Acceptance tests

`backend/tests/test_poa_exempt.py` (19 tests) pins: the CMS file parse, the `--from-dir` trap, FY URLs, grading (exempt SDx and PDx not graded, reportable still graded, no list = unchanged, DPO opportunity skipped), keys (IP to E, OP untouched, no list = unchanged, editor route, **Excel template upload route**, one-time correction), the generator **over 200 seeds** (removing the exclusion makes it fail), `/codes/describe`, and `/codes/status`.

Verified in the browser against the **real FY2027 list** (98,403 CM codes loaded):

| Action | Result |
|---|---|
| Coder types PDx Z38.00 | POA greyed E |
| Coder adds SDx Z87.891 | POA greyed E |
| Coder changes SDx to I10 | POA cleared to blank |
| Coder saves | draft stored PDx Z38.00 **E**, SDx Y92.9 **E**, Z87.891 **E** |
| Key editor opened | exempt lines already greyed E |
| Auditor screen | exempt claim lines locked E |

There was no overflow and there were no console errors.

## 8. Notes

- Auditor assignments generated **before** this change keep their claims. A POA error planted on an exempt code stays correctable (§6). New allocations and rerolls never plant one.
- The authored-error editor blocks POA errors on exempt codes **on screen**; the server doesn't re-check authored sets.
